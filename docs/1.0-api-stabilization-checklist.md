# 1.0 API stabilization checklist

Tracks what must freeze before 1.0: error-code stability, view-lifetime
rules, snapshot format, and the `Scene` vs `WorkerScene` parity table.
Split out of #108; closes #123.

Status words: **frozen** (do not change without a major bump),
**shaped** (landed, see issue), **open** (must resolve before 1.0).

## 1. Error codes — frozen set, frozen meaning

`FastMeshErrorCode` (`packages/fast-mesh-wasm/src/core.ts`) is the stable,
machine-readable contract. The current set is **frozen** — 12 codes:

`UNKNOWN_MESH`, `UNKNOWN_FIELD`, `UNKNOWN_SECTION`, `INVALID_ARGUMENT`,
`INVALID_INDEX`, `STALE_BVH`, `STEP_NOT_OPEN`, `CORRUPTED`,
`OUT_OF_MEMORY`, `STALE_LOOPS`, `STALE_SELECTION`, `INSTANCE_POISONED`.

Frozen rules (all verified in `core.ts`):

- A Rust error reading `<CODE>: <text>` with a known code becomes a
  `FastMeshError` with that code; any other message (including an unknown
  `PREFIX: `) passes through unchanged — a foreign error is never
  relabelled.
- A trap (Rust panic), V8/JSC stack exhaustion, or Firefox
  `InternalError` poisons the instance: every later call throws
  `INSTANCE_POISONED` without entering WebAssembly. Recovery is
  reload-the-module only.
- The worker boundary preserves codes: engine errors cross as
  `{ code, message }` (`worker/protocol.ts`, `worker/engine.ts`) and the
  client rethrows them as `FastMeshError` (`worker/client.ts`).

- [ ] Decide and document the policy for *adding* a code (new
  `FastMeshErrorCode` member): allowed in a minor, or major-only?
- [ ] Decide whether any code is still missing (e.g. a dedicated code
  for the `importGLTF` unsupported-feature throws, currently surfaced
  through `INVALID_ARGUMENT`-style errors).

## 2. View-lifetime rules — frozen

`MeshViews` (`packages/fast-mesh-wasm/src/views.ts`) are zero-copy views
over wasm memory:

- A view is valid **only until the next scene call that may allocate or
  move buffers** (any edit, add, undo, query, …). Re-acquire views after
  every scene call; never keep them across one.
- `new Scene({ debug: true })` wraps views in a `Proxy` (`ViewGuard`)
  that warns once when a kept view is read after the epoch moved or
  memory growth detached it.
- `WorkerScene.views(mesh)` returns **mirrors** (copies), not wasm
  views: each getter returns the current mirror, which is replaced when
  slot counts change or a buffer turns on/off — so the same
  get-right-before-use rule applies. `values()` additionally opts the
  values mirror on (`worker/client.ts`).

- [ ] Freeze the rule as stated (no API change needed — it is already
  the documented contract in `views.ts`).

## 3. Snapshot format — open

There is **no library-level scene serialize/restore API** (no
`saveProject` / `exportScene` in `packages/fast-mesh-wasm/src`).
What exists:

- The showcase project file (`.fmsproj.json`, `PROJECT_VERSION = 1`,
  `examples/showcase/src/load/project.ts`): JSON, forward-tolerant
  loader (unknown fields ignored, newer `version` still loads, invalid
  entries dropped), geometry as base64 little-endian f64/u32. It is
  **showcase-scoped**, not a library guarantee.
- The React `SceneSnapshot` (`src/store/snapshot.ts`): an immutable UI
  snapshot for rendering, not a persistence format.

- [ ] Decide what 1.0 promises: a library-level snapshot
  export/import, or "no stable persistence format in 1.0 — the
  showcase `.fmsproj.json` stays showcase-scoped".
- [ ] If a format is promised: versioning, tolerance rules, and
  placement/scale encoding.

## 4. `Scene` vs `WorkerScene` parity

`SceneLike` (`src/scene-like.ts`) is the shared surface the renderer
adapters depend on (`views`, `matrix4`, `placement`, `section`,
`sectionPlane`, `onChanges`, `commitFrame`, `drag`, optional `coloring`
/ `bounds`). Everything else differs as follows (verified against
`src/scene.ts`, `src/worker/client.ts`, `src/worker/protocol.ts`):

| Capability | `Scene` (sync) | `WorkerScene` (async where noted) |
| --- | --- | --- |
| Placement scale (#103) | `setPlacement` takes `scale`; `Placement.scale` always present; `matrix4`, bounds, `measure`, distance queries follow | **Gap — no scale**: `setPlacement` request carries rotation + translation only; `Placement.scale` documented "absent on hosts that do not track scale" |
| `measure` (#115) | Sync; `{ area, volume \| null, closed, volumeReason, boundaryLoops, nonManifoldEdges, orientationConflicts }` | **Gap — no `measure`**: no query kind, no client method (cf. `raycast` / `closestPoint` / `meshDistance`, which exist as promise queries) |
| Selection (#106) | `select` / `selectGrow` / `selectShrink` / `selectInvert` / `selectionAlive` / `isolate`; `STALE_SELECTION` contract | **Gap — no selection API** on the worker client |
| IO exporters (#104) | `exportSTL` / `OBJ` / `PLY` / `glTF` take `SceneLike` — work on either host; `applyPlacement` (default `true`) maps through `matrix4` | Same (works on mirrors); no worker round-trip needed |
| glTF import / Draco (#120, #121) | `importGLTF` (sync; `KHR_draco_mesh_compression` throws) / `importGLTFAsync` (+ Draco) return plain arrays for `addMesh` | Same — host-independent |
| Queries | Sync `raycast` / `closestPoint` / `meshDistance` / `analyze` | Promise queries; state changes tracked per key via `status(...)` |
| Node.js (#107) | `fast-mesh-wasm/node`: wasm loads on import, `init()` is a parity no-op; blocks the event loop per call | Browser-first; Node via `createWorker` + `worker_threads` adapter (see `docs/cookbook/headless-node.md`, `test/harness/node-worker.mjs`); single-threaded engine |

- [ ] Decide per gap row: close it (worker `measure`, worker
  selection, worker placement scale) or document it as a permanent
  1.0 boundary ("sync `Scene` for measure/select/scale; worker for
  off-thread adds/queries").
- [ ] Note: `docs/cookbook/headless-node.md` currently implies
  `WorkerScene` has async `measure` ("the same calls are async
  queries (`measure` etc. return promises)") — true only if the
  `measure` gap is closed; otherwise the recipe needs a correction.

## 5. Recently landed API shapes (do not regress)

- **#103 — placement scale**: `world = rotation · (scale · local) +
  translation`; default `[1, 1, 1]`; `measure` reports world units;
  `analyze` local distances are unscaled under scale.
- **#104 — `fast-mesh-wasm/io`**: four exporters + `importGLTF` /
  `importGLTFAsync`; only live triangles written; colors/normals ride
  along; glTF is one node/mesh/`TRIANGLES` primitive, no Draco on
  export.
- **#106 — selection contract**: `VertexSelection` is a snapshot
  (mesh + ids + content stamp); topology edits invalidate
  (`STALE_SELECTION`), placements do not; `isolate` returns the
  re-stamped selection to keep.
- **#115 — tolerant `measure`**: area always; `volume` is the absolute
  signed sum, `null` with `volumeReason: "open" | "non-manifold"` when
  not watertight; strict readers require `orientationConflicts === 0`.
- **#107 — Node gap documented**: sync `Scene` is the recommended
  headless path; `WorkerScene` in Node needs the `createWorker`
  adapter.
