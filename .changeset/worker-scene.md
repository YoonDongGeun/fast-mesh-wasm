Add `fast-mesh-wasm/worker` (browsers): `createWorkerScene(options?)` runs the `Scene` engine in a Web Worker and resolves to a `WorkerScene` with the same methods. Handles are returned at once; state changes are fire-and-forget and report progress through `status(key)` / `onStatus`; queries (`raycast`, `closestPoint`, `meshDistance`, `intersects`, `findContacts`, `analyze`, `fetchFieldValues`, `fieldStatus`, `sectionGap`) and `edit` / `repair` return promises. Call `commitFrame()` once per animation frame: it sends the frame's requests as one batch and delivers the change records of the results received, whose dirty ranges were transferred into main-thread mirrors, so `views`, `matrix4`, `placement`, `section` and `sectionPlane` stay synchronous and the three.js adapter works unchanged. Requests run in order; superseded colouring, section and drag-move requests are dropped before they start, and results older than what is shown are ignored. Drags are optimistic (the placement follows the pointer at once; `end` and `cancel` are synchronous). After a trap every call fails with `INSTANCE_POISONED` until `restart()`, which starts a new Worker and replays the meshes, placements, fields, colourings and sections (history is cleared). The Worker script is loaded with `new Worker(new URL("./worker-entry.js", import.meta.url), { type: "module" })`; the `workerUrl` and `createWorker` options override it. The Worker scene is always eager and has no `beginStep` / `endStep` / `cancelStep` or `takeChanges`.

The three.js adapter (`bindMesh`, `bindSection`, `attachTransformControls`) now accepts any `SceneLike`, a new exported interface (`views`, `matrix4`, `placement`, `section`, `sectionPlane`, `onChanges`, `commitFrame`, `drag`) that both `Scene` and `WorkerScene` implement. This is a type-only change: code passing a `Scene` is unaffected.
